# 🗂️ Luz-Project

把一个项目从想法带到交付。适合筹备网站、小程序或内部系统，也可以用来接手已有项目。

商业项目从客户要办的事开始。第一次一起确认需求说明和系统方案，第二次确认功能与技术设计，第三次亲手操作 HTML Demo。随后定稿架构图、功能清单、业务规则与实施计划，进入工程实现、独立验收和运营。见[项目路线与确认事项](references/commercial-project.md)和[可编辑的仓储项目样例](templates/商业项目批次/README.md)。

仓储样例包含可在浏览器离线运行的交互原型，以及用于重建项目批次的事实文件。 [仓储原型 HTML](templates/商业项目批次/仓储履约演示.html)

## 它能帮你做什么

- **说清要做什么**。把零散的想法整理成需求、方案和功能清单，标出要和客户确认的事项。
- **知道下一步做什么**。把设计、开发、测试和交付排成可跟进的步骤，明确当前要审核的是哪份文件。
- **把项目文件放对地方**。把原始资料、客户对接材料和开发资料分开，代码、配置和数据库变更都有清楚的存放位置。

## 可以直接套用的模板

- 用中文 README 介绍项目用途、主要功能、技术架构和启动方式，方便开发者从仓库首页接手。 [README 模板](templates/项目骨架/README.md) · [项目目录规范](references/project-structure.md)
- 按沟通、报价、试用和验收的顺序准备对接文件。每份都有示例和填法。 [对接资料](templates/02-对接资料/README.md)
- 把功能、开发、测试、上线和运维的记录留在一处。 [开发资料](templates/03-开发资料/README.md)
- 调研报告、工作说明和汇报可以共用一套文档版式。 [通用文档模板 PDF](templates/通用模板/通用文档模板.pdf)
